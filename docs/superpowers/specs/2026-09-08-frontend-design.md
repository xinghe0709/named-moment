# “此刻有名”前端 MVP 设计规格

## 1. 目标与范围

在现有 Spring Boot 项目中增加一体化静态前端，完成以下闭环：

1. 用户写下一段至少 5 字、至多 2000 字的日记或想法。
2. 页面调用 `POST /api/emotions/match`，在真实等待期间解释系统正在做什么。
3. 页面展示情感指纹和按匹配度排序的三个真实概念。
4. 用户选择最像自己的一个概念并调用 `POST /api/emotions/records` 保存。
5. 私人档案馆调用 `GET /api/emotions/records` 展示记录，并可调用 `DELETE /api/emotions/records/{id}` 删除。

首版不包含账户、图片输入、分享、搜索筛选和后台管理。

## 2. 设计决策

### 视觉世界

采用“背光玻璃馆藏墙”：整页是一面由黑色金属窗框分隔的手工压花玻璃墙。未发生交互时接近日光和透明；候选概念出现时，三个窗格被不同强度的颜色从背后点亮；用户保存时，选中的窗格完成一次缓慢而确定的增亮。

选择依据：

- 三个候选天然对应三个独立窗格，不需要通用卡片组件。
- “选中即点亮”把保存行为表达为自我确认，而非普通收藏。
- 档案馆可以扩展为持续生长的窗墙，视觉语言保持统一。
- 它避开本品类常见的米白日记纸 + 衬线标题，也避开黑底霓虹 AI 神谕。

已选高保真基准：`.impeccable/mocks/home-b-approved.png`。

### 方向比较结论

- 可变字体标本：词汇主题明确，但多语言字形支持不稳定，档案态也容易退化为排版展览；保留其“用尺度而非装饰建立层级”的纪律。
- VU 表桥：匹配度表达清晰，但会把私人感受简化为仪表读数；保留其“颜色只用于真正重要状态”的纪律。
- 云层采石场：想象力强但产品任务不够清晰；保留大面积安静区域与单一主动作。
- 构成主义宣传列车：动作明确但与私密表达的使用场景冲突；仅保留结构上的果断，不借用其图形服饰。
- 热带拼贴唱片：可探索但信息密度过高；保留每个馆藏对象都应有独立轮廓的要求。

## 3. 视觉 Token

| 名称 | 值 | 用途 |
|---|---|---|
| `mullion` | `#171918` | 金属窗框、主要文字、主操作 |
| `seeded-glass` | `#E9ECE7` | 主玻璃底色 |
| `mist-glass` | `#C9D6D3` | 次级窗格与安静状态 |
| `memory-cobalt` | `#1646B8` | 首选概念、当前聚焦、主确认状态 |
| `source-amber` | `#F2A93B` | 可靠来源与细小状态提示 |
| `archive-oxblood` | `#7A1F2B` | 第三候选与档案中的少量深色节奏 |

色彩策略为完整角色色板，但高饱和颜色只在候选、来源和选择结果中占据整块窗格；不把颜色撒成小图标或渐变装饰。

字体使用系统可用的人文无衬线组合：中文以 `PingFang SC`、`Hiragino Sans GB` 为主，拉丁文字以 `Avenir Next` 为主。概念名称依靠尺寸和字重建立地位，不使用默认高对比衬线或装饰性等宽标签。

## 4. 页面结构

### 输入态（桌面）

```text
┌────────品牌窗格──────────────────────────┬──私人档案馆──┐
├────────承诺窄窗──┬───────────────────────┼──真实概念────┤
│                  │ 告诉我一个你无法       │              │
│ 这种感觉，       │ 解释的瞬间。            ├──可靠来源────┤
│ 世界上也许       │                        │              │
│ 早已有名字。     │ [大面积无边框输入区]    ├──三个答案────┤
│                  │                        │              │
├──────────────────┴───────────────────────┴──────────────┤
│                    为此刻寻找名字                        │
└─────────────────────────────────────────────────────────┘
```

### 结果态（桌面）

```text
┌──情感指纹────────┬────────最接近的概念──────────┬──候选 02──┐
│ 你写下的此刻      │ 01 词汇 / 语言 / 匹配度       │ 词汇      │
│ 核心意义          │ 大字号含义与匹配解释          ├──候选 03──┤
│ 简短描述          │ 来源链接 + “这就是我的感觉”   │ 词汇      │
└──────────────────┴──────────────────────────────┴───────────┘
```

第一候选为最大窗格，第二和第三候选纵向排列。所有事实字段用文本节点渲染，避免把模型或用户文本作为 HTML 注入。

### 档案馆（桌面）

```text
┌──档案说明────────────┬──已收藏数量──┐
├──记录 01（宽）────────┼──记录 02─────┤
│ 原始文字 / 词汇 / 日期 │ 原始文字     │
├────────记录 03─────────┴──记录 04─────┤
└───────────────────────────────────────┘
```

记录按返回顺序展示。删除使用页内二次确认，不弹出浏览器原生确认框。

### 移动端

所有窗格按阅读顺序变为单列；金属分隔线保持真实厚度。品牌与档案入口同排；输入区至少占首屏一半；三个候选依次排列；主操作保持 48px 以上触控高度。移动端不保留复杂跨行布局，也不横向滚动。

## 5. 状态与动效

- 输入不足：按钮禁用，并用明确文案说明至少 5 字。
- 分析中：依次显示“读懂情感重心”“在世界语言中寻找”“核对来源和解释”，不显示虚假百分比。
- 匹配成功：窗格从自然日光缓慢增亮；内容默认可见，动效只是增强。
- 保存中：只禁用当前候选操作；成功后显示“已收藏到私人档案馆”。
- 接口错误：在当前窗格内展示服务返回信息，并提供返回书写或重试的动作。
- 空档案：保留完整玻璃墙，只显示“还没有收藏的此刻”和返回输入入口。
- 删除确认：第一次点击显示“再点一次确认移出”，数秒后自动恢复。
- `prefers-reduced-motion: reduce` 下取消所有过渡和状态亮度动画。

## 6. 无障碍与内容规则

- `html` 使用 `lang="zh-CN"`，主导航、表单、结果和档案使用语义标签。
- 所有可点击窗格使用原生 `button` 或 `a`；键盘焦点不得仅靠颜色表达。
- 全局提供 `:focus-visible` 高对比轮廓。
- 状态区使用 `aria-live="polite"`，错误使用 `role="alert"`。
- 来源链接在新窗口打开，并带 `rel="noopener noreferrer"`。
- 匹配度显示为“94% 接近”，不是诊断概率。
- 不在界面中暴露 RAG、Embedding、工具调用等技术术语。

## 7. 组件与媒介清单

| 可见元素 | 实现媒介 | 约束 |
|---|---|---|
| 黑色窗框与不规则网格 | CSS Grid + 边框 | 桌面 6px，移动端 4px |
| 压花玻璃纹理 | `assets/seeded-glass.png` | 仅作低透明度表面材料，不承载内容 |
| 标题、输入、概念与档案内容 | 语义 HTML | 不栅格化文字 |
| 蓝、琥珀、酒红背光 | CSS 纯色层 | 不使用渐变 |
| 选中增亮与状态切换 | CSS transition + JS 状态 | 支持 reduced motion |
| 图标 | 不使用 | 文案足以说明动作 |

## 8. 自我批评与修正

最初风险是把玻璃做成常见的半透明“glassmorphism 卡片”。修正方式是：全页只有一面连续的建筑网格，窗格不悬浮、不圆角、不使用模糊背景和层层阴影。第二个风险是让材料抢走输入内容；因此压花纹理只以低不透明度出现，主输入窗格更清晰，彩色窗格只服务真实性和选择状态。第三个风险是三个结果再次变成等权卡片；因此第一候选拥有明显更大的空间，第二、第三候选作为邻接窗格，层级由构图而非徽章制造。

## 9. 验收标准

- 首页、结果和档案三个状态在 1440px 与 390px 宽度下无横向溢出。
- 用户可完全使用键盘完成输入、匹配、选择保存、打开档案和删除。
- 四类 API 均由真实页面调用，失败信息不会被误报为成功。
- 所有用户输入和模型返回内容以安全文本节点呈现。
- 构建产物保留方向契约中的 seed key `67ec61a6`。
- 高保真稿、实际桌面截图和移动端截图均保存在 `.impeccable/` 下用于复核。
