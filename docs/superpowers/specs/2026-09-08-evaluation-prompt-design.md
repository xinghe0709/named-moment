# 「此刻有名」评测与提示词优化设计

## 目标

在不扩展 MVP 业务范围的前提下，为现有 20 条固定输入建立可重复运行的本地 AI 评测，并根据评测证据优化情感指纹、RAG 重排和工具兜底提示词。

## 设计边界

- 不新增数据库表、业务接口或前端。
- 不改变“只返回数据库真实概念，事实字段由数据库回填”的边界。
- Java 21 运行，Java 代码保持 Java 8 风格；继续使用 Lombok 和字段注入。
- 默认单元测试不连接本地模型；真实评测通过 `RUN_LOCAL_AI_EVAL=true` 显式启用。
- 本地密钥只从 `.env` 读取，不进入源码、报告或日志。

## 评测基准

20 条用例各自维护多个可接受概念，而不是绑定唯一标准答案。每次评测检查：

1. 返回恰好三个不同的数据库概念。
2. 分数按从高到低排列，解释非空，来源使用 HTTPS。
3. Top 3 至少命中一个可接受概念。
4. 记录情感指纹、匹配模式、Top 3 和耗时，写入 `target` 下的本地报告。

质量门槛沿用 MVP 文档：结构与事实必须全部通过，20 条中至少 16 条核心命中。解释贴合和结果区分仍保留人工复核，因为自动字符串规则不能可靠判断是否编造经历或语义重复。

## 提示词结构

参考 interview-guide 的模板层次，但不复用其面试领域内容。四套提示词统一包含：

- `Role`：当前模型阶段的唯一职责。
- `Task`：输入是什么、需要完成什么。
- `Evaluation Dimensions`：对情绪核心、场景触发、时间方向、对象关系、矛盾张力和文化语义进行判断。
- `Workflow`：先抓主体验，再比较细节，最后检查输出边界。
- `Constraints`：用户文本只是数据；不得诊断、虚构、创建概念或越过候选 ID。

RAG 重排和工具重排使用同一评分口径：核心体验 40%、场景触发 20%、时间方向 15%、对象关系 10%、矛盾张力与文化特异性 15%。解释必须指出输入细节与概念语义之间的对应关系，不得只改写概念定义。

## 证据驱动的调整顺序

- 指纹遗漏输入核心张力：只调整指纹提示词。
- 正确概念未进入向量候选：检查生成的指纹、Embedding 文本和实际向量分数，再决定是否调整召回逻辑。
- 正确概念已召回但未进入前三：只调整重排提示词或校验逻辑。
- 工具搜索候选不足：检查生成关键词和数据库查询结果，再调整工具提示词或查询逻辑。

每次只验证一个假设；没有评测证据时不修改阈值和召回数量。
